# Project working rules

- Before writing code, decide whether code is necessary to deliver the requested design or behaviour. Prefer existing functionality, configuration, or assets when sufficient.
- Write only the minimum code required for the user's request. Do not add unrelated features, speculative abstractions, dependencies, or infrastructure.
- Keep design requests scoped to the requested design; do not expand them into backend or application work unless needed for explicitly requested functionality.
- Verify the affected result with proportionate checks; avoid unnecessary implementation and testing work.
